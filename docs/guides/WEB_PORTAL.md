# ToFan web portal

หน้าเว็บใหม่รวมอยู่ใน firmware เปิดได้โดยไม่ต้องมี `/WEB_Source` บน SD เปิด Admin mode บนเครื่อง แล้วเข้า IP ของเครื่องหรือ `http://192.168.4.1` ผ่าน AP เดิม หน้า WiFi Manager เดิมจะ redirect มาที่ `/#wifi` ไฟล์ใน `WEB_Source/` ที่มีอยู่ยังเก็บไว้เป็นต้นฉบับ แต่ไม่ได้ใช้เสิร์ฟเว็บใหม่

ครั้งแรกสร้างบัญชีผ่าน AP ของเครื่อง หากมีบัญชีเดิมใน `UsernameConfig` ระบบย้ายข้อมูลเข้าสู่บัญชีใหม่ให้ บัญชีใหม่จัดเก็บ salted password hash ใน NVS; session อยู่ใน RAM และหมดอายุหลัง 24 ชั่วโมงหรือ reboot ทุก API สำหรับไฟล์ การตั้งค่า และ OTA ต้องเข้าสู่ระบบ เว็บใช้ HTTP ในเครือข่ายของอุปกรณ์ จึงควรใช้งานบนเครือข่ายที่ไว้ใจและไม่ forward พอร์ตออกอินเทอร์เน็ต

## ใช้งาน

การแจ้งเตือนใช้ popup ปิดได้ ส่วนการยืนยันลบไฟล์ เปลี่ยนชื่อ และ OTA ใช้ modal ภายในเว็บ กด Escape เพื่อยกเลิกและกลับไปยังปุ่มเดิม ตัวเลือก select เปิดเป็นรายการใน modal ใช้ลูกศร/Home/End/Enter ได้ ปุ่มเลือกไฟล์และชื่อไฟล์ปรับตามธีมเว็บ; หน้าต่างเลือกไฟล์ในเครื่องยังเป็นของระบบปฏิบัติการ

Dashboard ใช้ snap ความกว้าง 3/6/9/12 คอลัมน์ ความสูง 220/300/380/460/540/620 px ทั้งเมาส์และคีย์บอร์ด Layout เดิมจะปัดเข้าขนาดใกล้ที่สุด บล็อกมีแถบเสียง พื้นที่ SD สัญญาณ WiFi และความคืบหน้าเพลง พร้อมกราฟ RAM ว่างจาก 45 จุดล่าสุดที่อุปกรณ์ส่งมา ไม่มีการสร้างข้อมูลกราฟจำลองในหน้าใช้งานจริง

ขนาดขั้นต่ำของบล็อกคำนวณจากเนื้อหาจริงและพื้นที่จอ: ไม่ย่อความกว้างจนปุ่มกับข้อความล้น และจะขยายความสูงตามชื่อเพลง/ข้อมูลที่ยาวขึ้นโดยไม่ใช้ scroll bar ภายในบล็อก ความสูงอาจเกินช่วงขนาดปกติเมื่อข้อความยาวมาก ปุ่มมุมล่างเป็นไอคอนย่อ/ขยายและยังใช้คีย์บอร์ดได้ เมนูมือถือเปิดจากปุ่มมุมขวาเป็นแผงรายการครบทุกหน้า แทนแถบเลื่อนแนวนอน

หน้า Account เปลี่ยนชื่อบัญชีพร้อมยืนยันรหัสผ่านปัจจุบันได้ เว้นรหัสผ่านใหม่ว่างเพื่อเก็บรหัสผ่านเดิม ชื่อใหม่บันทึกใน NVS พร้อม hash แบบ atomic และออกจากระบบหลังบันทึกเพื่อเข้าสู่ระบบด้วยชื่อใหม่

- Dashboard: เพิ่ม/ลบบล็อก ย้ายลำดับด้วยลูกศร ลากมุมล่างเพื่อปรับความกว้างและความสูง ใช้ Tab ไปที่มุมบล็อกและปุ่มลูกศรเพื่อปรับขนาดด้วยคีย์บอร์ด Layout จดจำใน localStorage ของเบราว์เซอร์ แยกตาม device ID และยังอยู่หลังรีบูตอุปกรณ์
- Files: รูปใน `/main/Pictures`, เพลงใน `/main/Musics`, วิดีโอใน `/main/Videos` ดูตัวอย่าง ดาวน์โหลด เปลี่ยนชื่อ ลบ และอัปโหลดได้ ชื่อไฟล์เดิมจะไม่ถูกเขียนทับ รายการจำกัด 250 ไฟล์แรกต่อโฟลเดอร์เพื่อควบคุมการใช้ RAM
- WiFi: SSID สูงสุด 32 bytes รหัสผ่าน 8–63 bytes หรือเว้นว่างสำหรับเครือข่ายเปิด รองรับเครือข่าย 2.4 GHz เปลี่ยนเครือข่ายแล้วจะ reconnect โดยคง AP จัดการไว้
- Settings: เสียง 0–100, step 2–5, auto-next, shuffle, inference และสี 6 ส่วนผ่านวงล้อสี/ช่องเลือกสี สีใช้ร่วมกันระหว่างจอและเว็บ ค่าตั้งอุปกรณ์บันทึกใน NVS ผลบันทึกแสดงจากอุปกรณ์หลังส่งคำขอ
- AI: ตั้งค่าบริการสนทนาเดิม เว้นช่องข้อมูลลับว่างเพื่อคงค่าเดิม

## เตรียมรูปแบบ local

เลือก JPG/JPEG/PNG/GIF แล้วเลือกรูปแบบครอปเต็มจอหรือเห็นทั้งภาพพร้อมขอบ ลากตำแหน่ง ซูม เลือกสีขอบ ขนาดเริ่มต้นอ่านจากจออุปกรณ์ (ปัจจุบันแนวนอน 320 × 240) ปรับขนาดเองได้สูงสุดด้านละ 4096 และรวมไม่เกิน 4 ล้านพิกเซล

ประมวลผลด้วย Worker + OffscreenCanvas ในเบราว์เซอร์ ไม่มี CDN หรือบริการแปลงภาพภายนอก รองรับ Chrome/Edge ที่มี API เหล่านี้ หากเบราว์เซอร์ไม่รองรับ ยังอัปโหลดต้นฉบับได้ การเลือก/ครอป/กดประมวลผลไม่ส่งรูปไปอุปกรณ์ ต้องกดอัปโหลดแยกต่างหาก

JPEG ปรับคุณภาพเพื่อพยายามให้ไม่เกินขนาดเป้าหมาย PNG เป็น lossless จึงไม่ใช้ quality slider ลดขนาด GIF รักษาเฟรม เวลา และจำนวนรอบเล่น พร้อมลดจำนวนสีตาม quality มีข้อจำกัดต้นฉบับ 16 MiB, 300 เฟรม, พื้นที่ patch รวม 24 ล้านพิกเซลเพื่อควบคุมหน่วยความจำ การแปลง GIF เป็น JPEG/PNG จะเก็บภาพนิ่งหนึ่งเฟรม พื้นหลังโปร่งใสจะถูกรวมกับสีขอบที่เลือก หากยังเกินขนาดเป้าหมายจะแจ้งให้ลดขนาดหรือคุณภาพเอง

วิดีโอ MP4/WebM/MOV ที่เบราว์เซอร์ถอดรหัสได้ แปลงเป็น Raw MJPEG (.mjpeg/.mjpg) ในเครื่องได้ที่หน้าไฟล์ โดยเลือกขนาดพอดีจอและคุณภาพ JPEG แล้วกดแปลงหรือแปลงและอัปโหลด จำกัดคลิปต้นฉบับไม่เกิน 2 นาทีและผลลัพธ์ไม่เกิน 256 MiB ไม่มีการส่งวิดีโอไปบริการภายนอก ตัวแปลงสร้าง 12 เฟรมต่อวินาทีและไม่รวมเสียง

จอ TFT เล่น .mjpeg/.mjpg ใน `/main/Videos` ได้จากเมนู Media / Photos & Video เล่นวนและกด Back เพื่อหยุด รองรับ baseline JPEG ขนาดไม่เกิน 640×480 และหนึ่งเฟรมไม่เกิน 512 KiB ใช้ PSRAM เก็บเฟรม เป้าหมาย 12 FPS; ความเร็วจริงขึ้นกับ SD/ขนาดภาพและงานอื่นที่ทำพร้อมกัน MP4 ยังไม่ถอดรหัสโดยตรงบนบอร์ด ต้องแปลงก่อน ภาพ PNG รองรับบน TFT เช่นเดิม

ไฟล์เกิน 8 MiB มีคำเตือนและยืนยันก่อนอัปโหลด จำกัดไม่เกิน 256 MiB และต้องมีพื้นที่ SD เหลือ ไฟล์รับผ่านชื่อชั่วคราวที่สุ่มขึ้น เมื่อส่งครบจึง rename เป็นชื่อจริง หากยกเลิก/ขาดการเชื่อมต่อจะปิดและลบไฟล์ชั่วคราว; ไฟดับกะทันหันอาจเหลือ `.upload-*.part` ที่ซ่อนอยู่ใน `/main` สามารถนำ SD ไปตรวจและลบไฟล์ชั่วคราวเหล่านี้ได้

## OTA

ใช้ **application `firmware.bin` ของ ESP32-S3** จาก `.pio/build/esp32-s3-devkitc-1-n16r8v/firmware.bin` ไม่ใช้ bootloader, partition table หรือ merged flash image พาร์ทิชัน OTA รองรับสูงสุด 5 MiB

เลือกไฟล์หรือวาง HTTP(S) URL แล้วกดยืนยัน อุปกรณ์ต้องหยุดเพลง/การอัดเสียงและการประมวลผล AI ก่อน URL ต้องเป็นลิงก์ดาวน์โหลดตรง ตอบ HTTP 200 และมี Content-Length ไม่ตาม redirect; HTTPS ใช้ certificate bundle ของ ESP-IDF และต้องตั้งเวลาได้ผ่าน NTP ไม่มี `setInsecure` ในเส้นทาง OTA ส่วน HTTP ไม่เข้ารหัสจึงเหมาะกับแหล่งดาวน์โหลดที่ไว้ใจในเครือข่าย local เท่านั้น

OTA ตรวจขนาด magic/segment count/chip ID ก่อนเขียน พักการควบคุมบนเครื่องและ inference ระหว่างอัปเดต ปฏิเสธการโอนพร้อมกัน ตรวจการเขียนและ `Update.end(false)` ก่อนตั้ง boot partition และ reboot หลังตอบกลับสำเร็จ หากส่งไม่ครบ/เขียนผิดพลาดจะ abort และไม่สลับไปเฟิร์มแวร์ใหม่ ข้อมูล SD และ NVS ไม่ถูกฟอร์แมต ไม่ใช่ระบบเซ็นรับรองผู้เผยแพร่หรือรับประกัน automatic rollback หากเฟิร์มแวร์ใหม่บูตแล้วมีบัก

## Build / validation

```powershell
cd web
npm ci
node build.mjs
node --test test/model.test.mjs
node test/browser.mjs
cd ..
pio run -e esp32-s3-devkitc-1-n16r8v
```

`build.mjs` bundle ไลบรารี GIF ไว้ในเครื่องและสร้าง `src/network/PortalAssets.hpp` เป็น gzip assets; ต้อง build เว็บใหม่หลังแก้ source เว็บ ไฟล์ header ถูกเก็บกับ source เพื่อให้ build PlatformIO ได้โดยไม่ต้องติดตั้ง Node บนเครื่อง build firmware

Browser test ใช้ Chrome ที่ติดตั้งใน Windows และ API จำลองใน localhost ตรวจ layout persistence, resize, settings, WiFi, การประมวลผลภาพจริงใน Worker, explicit upload, responsive mobile และไม่มี request ออกภายนอก ภาพตัวอย่างอยู่ใน `docs/build/web-preview/` ข้อมูลในภาพเป็นข้อมูลจำลอง

Native tests อยู่ใน `test/test_web_policy.cpp` และชุด media/recording/settings/UI flow เดิม ครอบคลุม path traversal, ชื่อไฟล์, ขนาด/ชนิด firmware, ลำดับ chunk/ไฟล์ซ้ำ/overflow พร้อม regression เดิม การอ่านเขียน SD จริง, WiFi จริง, TLS server จริง, การตัดไฟ และการ reboot จาก OTA **ยังต้องทดสอบบนอุปกรณ์** ไม่มีการแฟลชอุปกรณ์ระหว่างการทดสอบนี้

GIF dependencies: [gifuct-js](https://github.com/matt-way/gifuct-js), [gifenc](https://github.com/mattdesl/gifenc). ใช้งานตาม MIT license ของแต่ละ package

การครอป: เลือกรูป JPG/PNG/GIF หรือ Raw MJPEG (.mjpeg/.mjpg) แล้วเลือก preset เต็มจออุปกรณ์, 320×240 หรือกำหนดกว้าง/สูงเอง ลากกรอบบนภาพต้นฉบับเพื่อเลือกตำแหน่ง ใช้ซูมเพื่อปรับพื้นที่ครอป หรือใช้ปุ่มลูกศรขณะโฟกัสกรอบ ตัวอย่างด้านล่างแสดงผลลัพธ์ที่เลือก กดครอปและบีบอัดก่อนดาวน์โหลดหรืออัปโหลดไฟล์ที่เตรียมแล้ว การแก้กรอบจะยกเลิกผลลัพธ์เดิมเพื่อป้องกันส่งไฟล์ผิดตำแหน่ง

GIF และ MJPEG ใช้กรอบเดียวกันทุกเฟรมและคงจำนวนเฟรม โดยแสดงเฟรมแรกในตัวแก้ไข MJPEG ประมวลผลด้วย Worker ภายในเบราว์เซอร์ รองรับสูงสุด 1,440 เฟรม (2 นาทีที่ 12 FPS), ไฟล์ 256 MB, ผลลัพธ์ไม่เกิน 640×480 และ JPEG ต่อเฟรมไม่เกิน 512 KB ตามข้อจำกัดเครื่องเล่นบนบอร์ด ไฟล์วิดีโอ MP4/WebM ยังใช้ตัวแปลงวิดีโอเดิม ส่วนกรอบลากครอปนี้ใช้กับ Raw MJPEG

ไอคอนเว็บใช้ Font Awesome Free 7.2.0 คัดลอกจาก `WEB_Source` มาไว้ใน `web/fontawesome/` โดยคง license headers เดิมไว้ ใช้แทนสัญลักษณ์ในเมนู บล็อกสถานะ ปุ่มจัดการไฟล์ ปุ่มปรับขนาด ตัวเลือก และ modal ไฟล์ CSS และ WOFF2 รวมอยู่ใน firmware ผ่าน `build.mjs` จึงโหลดจากอุปกรณ์ได้โดยไม่ใช้ CDN หรืออินเทอร์เน็ต ไอคอนเป็นส่วนตกแต่งและยังคงชื่อปุ่มสำหรับ screen reader
